# line_vision — 경기장 흰 선 인식 (AI) 계획

목표: 카메라 화면에서 경기장 **양옆 경계선**을 AI(UFLD-v2)로 찾고,
"로봇이 경계선에서 몇 m 떨어져 있는지 / 몸이 몇 도 틀어졌는지"를 토픽으로 낸다.
→ task_master 가 이걸로 `y_field`(경기장 중심 기준 로봇 좌우 위치)를 보정해서
   경기장 밖으로 가는 빈 틈을 고르지 않게 한다.

마감: 10/27. 지금(10/1) 기준 약 3주 반.

---

## 0. 큰 그림 (먼저 이것만 이해하면 됨)

```
[로봇 카메라] ──사진──▶ [AI 모델 UFLD-v2] ──선 위 점들(픽셀)──▶ [바닥 좌표로 변환]
                                                              │
                                     [직선 맞추기] ◀───────────┘
                                          │
              경계선까지 거리(m), 틀어진 각도(도)  ──토픽──▶ task_master
```

- **AI 가 하는 일은 딱 하나**: 사진에서 "경계선이 화면 어디를 지나가는지" 점으로 찍어주기.
  장애물에 가린 부분도 이어서 찍어준다 (그렇게 학습시킬 거라서).
- 나머지(바닥 좌표 변환, 직선 맞추기)는 그냥 계산. obstacle_vision 의 `pixelToGround` 와 같은 식.

### 용어 정리
| 용어 | 뜻 |
|---|---|
| 데이터셋 | 학습용 사진 + 정답(라벨) 묶음 |
| 라벨링 | 사진마다 "선이 여기 있다"고 사람이 점을 찍어 정답을 만드는 일 |
| 학습(train) | 모델이 사진을 보고 정답을 맞히도록 반복해서 고치는 과정. GPU 가 있으면 훨씬 빠름 |
| 파인튜닝 | 처음부터 학습하지 않고, 도로 차선으로 이미 학습된 모델을 가져와 우리 데이터로 조금 더 학습. 데이터가 적어도 잘 됨 |
| train / val | 학습에 쓰는 사진 / 학습에 안 쓰고 성능 확인에만 쓰는 사진 (보통 8:2) |
| 가중치(.pth) | 학습 결과 파일. 모델의 "뇌" |
| ONNX | 모델을 PyTorch 없이도 돌릴 수 있게 바꾼 공용 파일 형식 |
| OpenVINO | 인텔 CPU/내장그래픽에서 모델을 빠르게 돌려주는 인텔 라이브러리. 로봇 PC(i5 11세대, GPU 없음)용 |
| 추론(inference) | 학습 끝난 모델로 실제 사진을 넣어 결과를 뽑는 것 (로봇에서 하는 일) |

### 왜 UFLD-v2 인가
- 차선을 "선 하나 통째로" 예측해서 **장애물에 가려도 이어서 그려줌**.
- ResNet18 버전은 가벼워서 **GPU 없는 i5 11세대에서도 OpenVINO 로 돌릴 만함** (1단계에서 실제로 재봄).
- 공식 코드: https://github.com/cfzd/Ultra-Fast-Lane-Detection-v2

### 무엇을 찾게 할지 (선 슬롯)
UFLD 는 "선 번호(슬롯)"를 정해놓고 슬롯마다 있음/없음 + 위치를 예측한다. 우리는:
- 슬롯 0: **왼쪽 경계선**
- 슬롯 1: **오른쪽 경계선**
- (시작선/도착선은 일단 안 함. 필요해지면 나중에 슬롯 추가)

⚠️ 경기장 안쪽 다른 흰 선, 주변 흰 배경은 **라벨링하지 않는다** → 모델이 "이건 선 아님"을 배움.

## 3. 라벨링 (10/6 ~ 10/10)

### 3-1. 도구: labelme (설치 쉬움, 로컬에서 동작)
- `pip install labelme` → 사진 폴더 열기 → **Create LineStrip**
- 라벨 이름: `left`, `right` (딱 이 두 개만)

### 3-2. 규칙 (팀원이 같이 해도 결과가 같게)
1. 경계선은 직선이라 **양 끝 2점**만 찍으면 됨 (휘어 보이면 3~4점)
2. **장애물에 가려진 부분도 이어서 찍는다** ← 이게 "가려져도 인식"의 핵심
3. 화면 끝까지 이어지면 화면 끝에 점을 찍는다
4. 테이프 **가운데**를 찍는다
5. 경기장 안쪽 다른 흰 선, 주변 흰색은 **안 찍는다**
6. 어느 쪽이 왼쪽인지 헷갈리면: 로봇이 도착 지점을 보고 있다고 했을 때 경기장의 왼쪽 선 = `left`
   (로봇이 많이 틀어져서 화면에 `left` 하나만 오른쪽에 보여도 이름은 `left`)

### 노드가 하는 일
1. 카메라 이미지 구독
2. OpenVINO 로 추론 → `left`/`right` 선 위 점들 (픽셀)
3. 점들을 바닥 좌표(m)로 변환 (obstacle_vision 과 같은 카메라 높이/틸트/내부값 사용)
4. 바닥 좌표에서 직선 맞추기 → 선마다
   - 로봇에서 선까지 좌우 거리 (m)
   - 선과 로봇 진행 방향 사이 각도 (도) = 몸이 틀어진 정도
5. `vision_interfaces/msg/FieldLines` 로 publish + 디버그 이미지

### 새 메시지 (안)
```
std_msgs/Header header
bool left_found
float32 left_y_m        # 로봇 기준 왼쪽 경계선까지 (+왼쪽)
bool right_found
float32 right_y_m       # 로봇 기준 오른쪽 경계선까지 (-오른쪽)
float32 heading_deg     # 경계선 기준 로봇이 틀어진 각 (+왼쪽으로 돌아 있음)
```
